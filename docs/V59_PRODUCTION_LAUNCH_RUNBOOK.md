# V59 生产上线操作手册

## 目标

仅当真实支付、正式邮件、自定义域名、恢复任务和备份证据均通过后，才允许发布商户站点。测试环境可以继续使用 Sandbox，但不能勾选 V59 Live 验收项或绕过发布门禁。

## 一、PayPal Live

1. 在 PayPal Developer Dashboard 创建 Live App。
2. 为当前商户站点保存 Live Client ID、Client Secret 和 Live Webhook ID，模式选择 `live`。
3. Webhook 地址使用正式域名：`https://商户域名/api/paypal/webhook`。
4. 至少订阅付款完成、付款失败或取消、退款完成相关事件。
5. 在“生产上线中心”运行 PayPal 检查。
6. 完成一笔可识别的小额真实订单，确认服务端 Capture 后订单才变为已支付。
7. 重放同一 Webhook，确认订单、库存和邮件不会重复处理。
8. 完成部分退款和全额退款，确认金额、状态及选择的补库存规则一致。

禁止把 Sandbox 凭据和 Live Webhook 混用。切换凭据后必须重新运行健康检查和 V59 Live 验收。

## 二、Resend 正式发件

1. 在 Resend 添加商户发件域名并完成 SPF、DKIM 等 DNS 验证。
2. 使用该域名的地址，例如 `orders@shop.example.com`，不能使用 `onboarding@resend.dev`。
3. 保存 API Key 和 From Email 后运行 Resend 检查。
4. 分别验证付款、发货、退款、找回密码和退订邮件。
5. 在订单通知和运营事件中确认失败记录可以重试，且不会重复发送同一种通知。

## 三、自定义域名

1. 在 Sites 绑定商户正式域名并配置返回的 DNS 记录。
2. 在平台后台“域名管理”录入同一主机名。
3. 通过正式域名打开后台后执行路由检查，确认 SSL 与绑定状态为 Active。
4. 检查首页、商品详情页 Canonical、PayPal 返回地址、密码重置、订单查询和退订链接均使用正式域名。

## 四、备份与恢复

1. 在“生产上线中心”创建已验证备份。
2. 系统将商户配置、商品、库存、订单、通知、退款、客户和运营记录写入私有 R2；支付与邮件密钥不会进入备份。
3. 点击“运行恢复演练”，系统会读取备份、校验 SHA-256、租户归属、格式版本和关键表，不修改生产数据。
4. 下载 JSON 导出并保存在平台约定的离线保管位置。
5. 系统每日自动创建一次备份，每个商户保留最近 14 个版本。

## 五、发布与回滚

1. 运行生产健康检查，所有检查必须在 24 小时内通过。
2. 完成 V59 的六项人工验收并保留对应订单号、Webhook 事件、通知和备份记录。
3. 创建发布申请，由站点所有者审批后发布。
4. 上线后观察支付、邮件、Webhook、库存和错误事件。
5. 发生阻断故障时，在版本记录中选择最近稳定版本回滚；资金和订单异常使用对账与补偿流程处理，禁止直接修改数据库。

## 上线阻断项

- PayPal 仍为 Sandbox；
- PayPal 或 Resend 检查失败或超过 24 小时；
- 发件地址仍为 `resend.dev`；
- 没有 Active/Verified 自定义域名；
- 没有通过校验的租户备份；
- V59 Live 付款、Webhook、退款、邮件、域名回调或恢复演练未确认；
- 存在未解决的失败运营事件。
